# Spanish coverage of the public website

Generated by `node tools/i18n-audit.mjs --md tools/I18N_SITE_COVERAGE.md --before <before.json>` (2026-10-10, release-platform v2240 (before) vs site-bilingual v2242 (after)).
Every route is rendered in headless Chromium in Spanish (?lang=es) at 1280 and 390 px, and in English at 1280 to compare. A string
counts as English left when it reads as English (common English words) or the English page shows the very same string and it still has
words once names, numbers and codes are removed. Text nodes, aria-label, title, alt, placeholder, the tab title and the meta description
are counted; brand and character names, cited source titles and tools/i18n-allow.json are not. Investor pages are owner-only and out of scope.
Flows (flow:...) are states a visitor reaches: request forms with the gateway live and sent empty, the bag, checkout and search.

All Spanish is a DRAFT pending review by the center's Spanish teacher (native speaker).

## How the Spanish site works

- **One switch, remembered.** The Español button (header, phone header, entry gate) or `?lang=es` turns the whole site Spanish; the choice is
  kept in this browser (localStorage `ff-lang`) on every page, including the prerendered addresses (/kids-shop, /habit-wash-hands ...).
- **Offered on first visit.** The entry gate has English · Español. A browser whose preferred language is Spanish also sees a one-line
  offer ("¿Prefieres español? Ver en español · No, gracias") until a language is chosen or the offer is declined.
- **Phrase tables.** `i18n-es.js` ... `i18n-es-8.js` (family pages, always loaded) and `i18n-es-site.js` (every other page, about 4,300 strings,
  downloaded only while Spanish is on, `?v=` = the build). Books, activities and captions have their own Spanish data files.
- **Tab title and meta description** follow the language (i18n.js `head()`), from the same tables.
- **Videos with voices** get the Spanish caption track as the default track while Spanish is on (captions.js, habits.js); every voiced
  clip has a `.es.vtt`. The Kids' Shop film has music only.
- **Forms.** Labels, options, validation and gateway messages are translated. A request sent from the Spanish site adds
  "[Idioma preferido: español / Preferred language: Spanish]" to its message, so the center can answer in Spanish (only when it fits the
  gateway's message limit). Confirmation emails are written by the intake gateway in the CRM repo, not by this site: a "Ver en español"
  link there is an open item for that repo.
- **SEO on a hash app.** Every prerendered page names its Spanish address with `<link rel="alternate" hreflang="es" href=".../page?lang=es">`
  plus `hreflang="en"` and `x-default`, and `og:locale:alternate es_US`. The Spanish address renders Spanish (crawlers that run JavaScript
  see it) and names itself as canonical once rendered. Limits: the static HTML in each page is English (the Spanish is applied by
  JavaScript), so a crawler that does not run JavaScript sees English at the Spanish address; true Spanish static pages (/es/...) would
  need the prerender to run a second time in Spanish, which doubles the committed pages. The 404 page carries both languages.
- **Adding a string.** Add the English (exactly as on the page) and its Spanish to `i18n-es-site.js`, run this audit, and keep
  `tests/i18n-site.test.js` green. Anything that must stay English goes in `tools/i18n-allow.json` (names and titles only).
